# Optional public-page analytics

Analytics remains disabled until both build-time variables, `VITE_GA_MEASUREMENT_ID=G-YFG3PYKMXG` and `VITE_ANALYTICS_FRAME_ORIGIN=https://analytics.plannix.co.uk`, and both web-service runtime variables, `GA_MEASUREMENT_ID=G-YFG3PYKMXG` and `ANALYTICS_FRAME_ORIGIN=https://analytics.plannix.co.uk`, are deliberately configured. `FRONTEND_ORIGIN` must identify the exact HTTPS application origin. Malformed or matching app/frame origins fail closed. None of these values is a secret. Do not add a tag snippet to `index.html` or enable these variables before the separate hostname is verified.

The analytics hostname must route to the existing Express web component with its transport `Host` preserved. The earliest Express boundary serves only `/analytics-frame.html` and `/analytics-frame.js` on that exact host; it rejects APIs, auth routes, the SPA and other paths. Add `analytics.plannix.co.uk` to the App Platform app, configure its DNS record, wait for managed TLS, and verify exact-authority ingress and both allowed and rejected paths before activation. The checked-in repository has no App Platform spec, so the live ingress configuration must be verified separately. Reusing the web component should not add a component charge, but it shares service capacity and bandwidth.

Only explicit analytics consent permits a frame. The parent allows signed-out, parameter-free `/`, `/features` and `/contact` visits and sends fixed titles, canonical URLs and sanitized public referrers. The hidden frame uses `sandbox="allow-scripts allow-same-origin"` only because its HTTPS origin differs from the app origin. Parent and frame validate exact message source and origin. The main document's CSP permits the configured frame origin, not Google hosts. Google script and connection permissions exist only in the frame's CSP; its referrer policy is `no-referrer`. Enhanced measurement, Google signals and advertising features must remain off. The tag's automatic page view is disabled.

The frame sets `cookie_domain: 'none'` so GA cookies remain on the analytics hostname. On consent withdrawal, the parent asks the analytics frame to remove its GA cookies, waits at most 500 ms for an acknowledgement, then destroys the frame regardless of success. If no frame exists after a consented visit, it opens a cleanup-only frame that never requests the tag. Cookie cleanup can fail when storage or the frame is unavailable; transmitted requests cannot be recalled. Since the cookies are separate from the application hostname, the app cannot delete them directly. Browser storage restrictions may reduce visitor continuity or measurement. An intercepted local collection attempt proves neither Google acceptance nor Safari behaviour; verify those separately during a controlled rollout.
